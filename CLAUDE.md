## Структура
| Патека | Улога |
|---|---|
| `src/institutions.js` | **Единствен извор** на податоци за друштвата (СВТ, износи, рокови, контакти, датум на проверка). Само овој фајл се менува при ажурирање на услови. |
| `src/App.jsx` | Клиентски дел (CustomerView) + рутирање кон панелот (`#admin`). |
| `src/AdminView.jsx` | Контролен панел: најава со лозинка, листа на барања, статус, CSV, бришење. |
| `api/applications.js` | Vercel serverless API: POST (јавно) / GET, PATCH, DELETE (со `ADMIN_PASSWORD`). Postgres преку `DATABASE_URL`. Табелата се создава сама. |
| `index.html` | Meta-тагови (SEO). Бројот на друштва во описот треба да одговара на `activeInstitutions.length`. |

Деплој: Vercel, автоматски од гранката `main` (проектот е поврзан со GitHub `ikikokredit/kikocredit`).

## Постапка: проверка/ажурирање на условите (месечно)
1. За секое друштво во `src/institutions.js` отвори го `source` (и тарифник/репрезентативен
   пример ако постои) и спореди: `minAmount`, `maxAmount`, `minMonths`, `maxMonths`, `svt`,
   `interestRate`, `email`, `phone`, `website`.
2. `svt` се менува САМО ако е прочитана од сајтот (репрезентативен пример или тарифник);
   тогаш `svtVerified: true`. Ако сајтот не објавува СВТ, остави ја старата вредност и
   `svtVerified: false`, а во `notes` запиши што недостасува.
3. Ниедна `svt` не смее да е > `SVT_LEGAL_MAX` (60 %) — тоа е законскиот максимум што го
   наведуваат самите друштва.
4. Друштво што не постои / е во ликвидација / чиј домен пренасочува кон друго → `active: false`
   + објаснување во `notes`. Не бриши записи (id-то се користи во базата).
5. Ажурирај `verifiedAt` за секој проверен запис и `DATA_UPDATED` / `DATA_UPDATED_LABEL` на врвот.
6. `npm run check:data && npm run build`, па отвори Pull Request со табела „старо → ново“
   по друштво и линкови до изворите. Не спојувај (merge) без потврда од сопственикот.

## Постапка: барања (leads)
- Клиентот прави `POST /api/applications`; ако базата не е поставена, API враќа 503, а
  клиентот сепак покажува „испратено“ (барањето оди и по e-mail преку EmailJS).
- Личните податоци НЕ се чуваат во прелистувачот (localStorage) — стар клуч
  `kiko_applications` се брише при стартување.
- EmailJS клучевите во `src/App.jsx` се јавни по дизајн на EmailJS; ограничувањата се
  поставуваат во EmailJS-панелот (дозволени домени).
